Target triples

LLVM.Triple — Type
LLVM.Triple(str::AbstractString)

A target triple, like x86_64-unknown-linux-gnu, interpreted by the loaded LLVM library like C++'s llvm::Triple. The string is used as it is, like C++ passes do with Triple(M.getTargetTriple()): spellings that LLVM only understands after normalization, like the OS of x86_64-w64-mingw32, are not recognized. Use normalize to get a normalized triple.

Two triples are equal if they are spelled the same. string(triple) returns the string.

Properties

triple.arch
triple.vendor
triple.os
triple.environment
triple.object_format

The architecture, vendor, operating system, environment and object file format that LLVM derives from the triple, as symbols named like LLVM does (e.g., :x86_64, :i386, :aarch64, :apple, :linux, :windows, :gnu, :elf, :macho, :coff), or :unknown. The names come from the loaded LLVM library, so other versions of LLVM may know about more of them, or name them differently (e.g., the architecture of amdgcn-amd-amdhsa is :amdgcn before LLVM 23, and :amdgpu since). The predicates below don't depend on such names. The object format defaults to the one of the operating system when the triple doesn't specify it, so triple.object_format == :elf is C++'s isOSBinFormatELF().

See also: isx86, isaarch64, isarm, isthumb, isriscv, isppc, isnvptx, isamdgpu, isspirv, iswasm, isdarwin, iswindows, islinux.

Target machines

LLVM.TargetMachine — Type
TargetMachine

Primary interface to the complete machine description for the target machine.

All target-specific information should be accessible through this interface.

Properties

tm.target

The target of the target machine.

tm.triple

The target triple of the target machine.

tm.cpu

The CPU of the target machine.

tm.features

The feature string of the target machine.

Ownership

A target machine is consumed by TargetMachineBuilder(tm), and thus by LLJIT(; tm), which take ownership of it. A consumed target machine can't be used anymore, and disposing of it does nothing, so that it can be disposed of unconditionally, e.g., using the do-block form of its constructor.

Subtargets

LLVM.SubtargetInfo — Type
LLVM.SubtargetInfo

The CPU and features of a target, as LLVM's tables for that target describe them (C++'s MCSubtargetInfo). Enabling a feature also enables the features that it implies, and disabling a feature also disables the features that imply it; when a feature string sets a feature more than once, the last setting wins.

Properties

sti.triple

The target triple of the subtarget, as a string like tm.triple (use LLVM.Triple to interpret it).

sti.cpu

The name of the CPU. Targets may fill it in, e.g., X86 uses "generic" when no CPU is given.

sti.features

The feature string of the subtarget, e.g., "+avx2,-fma". Targets may extend the feature string that the subtarget was created with, e.g., X86 prepends the features that the triple implies, like +64bit-mode.

See also: LLVM.hasfeature, LLVM.hasfeatures, LLVM.processor_features.

LLVM.hasfeature — Function
LLVM.hasfeature(sti::LLVM.SubtargetInfo, name::AbstractString)

Check whether the subtarget has the feature of the given name (e.g., "avx2", without a + or - flag) enabled, including when it is enabled because another feature implies it. Throws an ArgumentError if the target doesn't have a feature of that name (see LLVM.processor_features).

source
LLVM.hasfeatures — Function
LLVM.hasfeatures(sti::LLVM.SubtargetInfo, flags::AbstractString)

Check whether the subtarget matches all flags of a comma-separated feature string, e.g., "+avx2,-fma": whether it has every feature that is flagged with + enabled, and every feature flagged with - disabled. This is C++'s MCSubtargetInfo::checkFeatures as of LLVM 21, which checks every flag by itself, on every version of LLVM. Earlier versions of checkFeatures also checked the features that a flagged feature implies, and ignored unknown features, while later versions abort on them.

Throws an ArgumentError if a flag doesn't start with + or -, or names a feature that the target doesn't have (see LLVM.processor_features). Empty flags are ignored, so an empty string matches every subtarget.

LLVM.constant_offset — Function
LLVM.constant_offset(gep, dl::DataLayout)

Compute the offset in bytes that a getelementptr instruction or constant expression adds to its pointer operand, according to the data layout dl, or nothing if the offset isn't constant. The offset is a signed integer, computed with the index width of the pointer's address space, and returned as a BigInt.

Only GEPs that compute a single pointer are supported, not those that compute a vector of pointers.

LLVM.constant_offset(T::Type{<:Integer}, gep, dl::DataLayout)

Compute the offset like LLVM.constant_offset(gep, dl), but return it as an integer of type T (e.g., Int), throwing an InexactError if it doesn't fit.

LLVM.strip_and_accumulate_constant_offsets — Function
LLVM.strip_and_accumulate_constant_offsets(ptr::Value, dl::DataLayout;
                                           allow_non_inbounds=false)

Strip the constant offsets from the pointer ptr: getelementptr instructions and constant expressions with constant indices, as well as casts that don't change the address, like LLVM's Value::stripAndAccumulateConstantOffsets. Returns the base pointer and the accumulated offset in bytes, as a BigInt, which is computed as a signed integer of the index width of the pointer's address space. If nothing can be stripped, the result is (ptr, 0).

By default, only inbounds GEPs are stripped. With allow_non_inbounds=true, other GEPs are stripped as well, in which case the offset does not imply that the pointer is within the bounds of the object the base points to.

LLVM.strip_and_accumulate_constant_offsets(T::Type{<:Integer}, ptr, dl; kwargs...)

Strip the offsets in the same way, but return the offset as an integer of type T (e.g., Int), throwing an InexactError if it doesn't fit.

Disassembly

LLVM.Disassembler — Type
Disassembler

A disassembler for machine code of a specific target, which decodes raw bytes into textual assembly instructions.

See also: disassemble.

source
LLVM.dispose — Method
dispose(dis::Disassembler)

Dispose of the given disassembler.

source
LLVM.disassemble — Function
disassemble(dis::Disassembler, code::AbstractVector{UInt8}; address::Integer=0)

Disassemble the machine code in code, returning a lazy iterator of instructions. The address keyword specifies where the first byte of code resides in the target's address space, which is used to compute the address of every instruction.

Each instruction is a named tuple with fields:

  • address::UInt64: the address of the instruction;
  • size::Int: the number of bytes the instruction occupies;
  • text::Union{String,Nothing}: the textual representation of the instruction, or nothing if the bytes could not be decoded. In that case, size is 1 and disassembly resumes at the next byte, which may not be an instruction boundary on targets with fixed-width instructions.

The iterator borrows the disassembler, so it must be consumed before the disassembler is disposed of. The disassembler must not be used by multiple tasks concurrently.

Examples

Disassembler("x86_64-linux-gnu") do dis
    for (; address, text) in disassemble(dis, code; address=0x1000)
        println(string(address; base=16), ": ", something(text, "<invalid>"))
    end
end
source
disassemble(io::IO, dis::Disassembler, code::AbstractVector{UInt8}; address::Integer=0)

Disassemble the machine code in code, and print the instructions to io, one per line. Bytes that could not be decoded are printed as .byte directives.
